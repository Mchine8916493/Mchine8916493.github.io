汇编语言（Assembly Language）是介于机器码与高级语言之间的底层编程语言。它直接映射到 CPU 指令集，是理解计算机工作原理、进行底层优化、驱动开发、嵌入式开发和逆向工程的基础。本文从零开始系统梳理汇编语言的知识点。

# 一、汇编语言是什么

## 1.1 从机器码说起

CPU 只认识二进制，一条指令在机器中就是一串 0 和 1。例如 x86-64 上：

```
B8 01 00 00 00     ; mov eax, 1
```

这串字节可读性极差。汇编语言用助记符（Mnemonic）代替机器码：

```asm
mov eax, 1
```

汇编器（Assembler）负责把助记符翻译成机器码，反汇编器（Disassembler）做相反的工作。

## 1.2 汇编语言的特点

| 特点 | 说明 |
|---|---|
| 与硬件强相关 | 每种 CPU 架构（x86/ARM/RISC-V）有自己独立的指令集，不可移植 |
| 直接控制硬件 | 可访问寄存器、标志位、特殊功能寄存器、内存映射 I/O |
| 高效且可预测 | 程序员完全掌控每条指令，无编译器中间优化 |
| 语法较繁琐 | 语句极简，一个操作往往需要多条指令完成 |

## 1.3 为什么要学汇编

- **理解程序执行本质**：C 语言指针、栈、递归、数组下标的背后都是汇编语义
- **嵌入式/驱动开发**：启动代码、中断向量表、寄存器配置必须写汇编
- **性能优化**：编译器生成不了最优代码的热点可用汇编手写
- **逆向工程与安全**：分析恶意软件、漏洞利用、CTF 都必须读汇编
- **操作系统**：任务切换、上下文保存、系统调用入口本质是汇编

# 二、CPU 架构基础

## 2.1 主要指令集架构（ISA）

| 架构 | 类型 | 指令长度 | 代表 |
|---|---|---|---|
| x86 / x86-64 | CISC | 变长（1~15 字节） | Intel、AMD |
| ARM / AArch64 | RISC | 定长（32 位/64 位） | 手机、嵌入式、Apple M 系列 |
| RISC-V | RISC | 定长（32 位基线） | 开源架构，RISC 的教科书实现 |
| MIPS | RISC | 定长 32 位 | 经典教学架构 |

- **CISC（复杂指令集）**：指令多且功能复杂，如 x86 单条指令可完成内存操作
- **RISC（精简指令集）**：指令少且规整，绝大多数指令只在寄存器间操作，访存只能通过 load/store

## 2.2 寄存器

寄存器是 CPU 内部的高速存储单元，比内存快几个数量级，是汇编操作的核心对象。

### x86-64 通用寄存器（16 个，64 位）

| 寄存器 | 用途约定 |
|---|---|
| RAX | 累加器，函数返回值 |
| RBX | 通用，被调用者保存 |
| RCX | 计数，常作循环计数 |
| RDX | 数据，常配合 RAX 做除法/乘法 |
| RSI / RDI | 源/目的索引，常用于字符串操作与传参 |
| RBP | 帧指针（栈帧基址） |
| RSP | **栈指针（Stack Pointer）** |
| R8~R15 | 扩展通用寄存器 |

> 还有专用寄存器：RIP（指令指针）、RFLAGS（标志寄存器）、段寄存器、控制寄存器、XMM 等。

### ARM 用户模式通用寄存器（R0~R15）

| 寄存器 | 别名 | 用途 |
|---|---|---|
| R0~R3 | — | 传参/返回值 |
| R4~R11 | — | 变量（被调用者保存） |
| R12 | IP | 过程调用中间暂存 |
| R13 | SP | 栈指针 |
| R14 | LR | 链接寄存器（保存返回地址） |
| R15 | PC | 程序计数器 |

状态寄存器 **CPSR** 保存 **N/Z/C/V** 标志位（负/零/进位/溢出）、中断屏蔽位和处理器模式。

## 2.3 内存布局与寻址

程序运行时内存按段划分：

```
高地址 ┌──────────────┐
       │  栈 Stack    │  ← 向下增长（x86/ARM 均向低地址）
       ├──────────────┤
       │      ↓       │
       │  空闲区      │
       │      ↑       │
       ├──────────────┤
       │  堆 Heap     │  ← 向上增长
       ├──────────────┤
       │  BSS（未初始化全局变量） │
       ├──────────────┤
       │  数据段（已初始化全局变量）│
       ├──────────────┤
       │  只读数据（字符串常量等）│
       ├──────────────┤
       │  代码段 Text │
低地址 └──────────────┘
```

# 三、汇编语句格式

## 3.1 一般格式

```
[标号:] 助记符 [操作数1, 操作数2, 操作数3] [; 注释]
```

示例（NASM 语法，Intel 风格）：

```asm
start:              ; 标号，表示一条指令的地址
    mov  eax, 10    ; 把立即数 10 送入 eax
    add  eax, 5     ; eax = eax + 5
```

## 3.2 两种语法风格

| | Intel 风格（x86） | AT&T 风格（GNU，x86） |
|---|---|---|
| 操作数顺序 | `mov 目标, 源` | `movl 源, 目标` |
| 立即数 | `mov eax, 10` | `movl $10, %eax` |
| 寄存器前缀 | 无 | `%`（如 `%eax`） |
| 立即数前缀 | 无 | `$`（如 `$10`） |
| 内存寻址 | `[ebx+4]` | `4(%ebx)` |
| 指令宽度后缀 | 无 | `b/w/l/q`（如 `movb/movl`） |

> 了解 AT&T 风格很重要，因为 GCC 默认产出 AT&T 汇编、Linux 内核源码也大量使用。

## 3.3 ARM 汇编语法（GNU as）

```
[标号:] 助记符 {条件码}{S} 目标, 第一操作数, 第二操作数 ; 注释
```

```asm
adds r0, r1, r2    ; r0 = r1 + r2，且更新 CPSR 标志位（S 后缀）
mov  r3, r0, lsl #2 ; r3 = r0 << 2
```

# 四、指令分类详解

## 4.1 数据搬移指令

```asm
; x86
mov eax, 10        ; eax = 10
mov ebx, eax       ; ebx = eax
mov [addr], eax    ; 把 eax 存入内存地址 addr

; ARM
mov r0, #5         ; r0 = 5
ldr r1, [r2]       ; r1 = *(int*)r2 （加载）
str r1, [r2]       ; *(int*)r2 = r1 （存储）
```

要点：
- x86 允许 **内存↔寄存器** 直接搬移，但 **内存↔内存** 不允许
- ARM 是 load/store 架构，**任何访存必须经过 ldr/str 系列**
- 立即数（常数）直接编码在指令中

## 4.2 算术运算指令

```asm
; x86
add eax, 1         ; eax += 1
sub eax, ebx       ; eax -= ebx
inc eax            ; eax++
dec eax            ; eax--
imul eax, 10       ; eax *= 10
idiv ebx           ; edx:eax ÷ ebx，商→eax，余数→edx

; ARM
add r0, r1, r2     ; r0 = r1 + r2
sub r0, r1, #3     ; r0 = r1 - 3
rsb r0, r1, #0     ; r0 = 0 - r1 = -r1（反向减法，取负）
mul r0, r1, r2     ; r0 = r1 * r2
```

## 4.3 逻辑与移位指令

```asm
; x86
and eax, 0xFF      ; eax = eax & 0xFF（取最低字节）
or  eax, 0x0F      ; eax |= 0x0F
xor eax, eax       ; eax = 0（最快清零方式！）
shl eax, 2         ; eax <<= 2（无符号左移）
shr eax, 2         ; eax >>= 2（无符号右移）
sar eax, 2         ; eax >>= 2（算术右移，保留符号位）
not eax            ; eax = ~eax

; ARM
and r0, r1, #0xFF
orr r0, r1, r2
eor r0, r1, #0xFFFFFFFF   ; 异或全 1 即取反
bic r0, r1, #0x0F         ; 位清零（bit clear）
lsl r0, r1, #2            ; 逻辑左移
lsr r0, r1, #2            ; 逻辑右移
asr r0, r1, #2            ; 算术右移
ror r0, r1, #2            ; 循环右移
```

> `xor reg, reg` 是编译器生成**寄存器清零**的标准手法，因为它比 `mov reg, 0` 更短更快。

## 4.4 比较与条件跳转

```asm
; x86
cmp eax, 10        ; 计算 eax-10，只更新标志位，不保存结果
je  label          ; 相等则跳（Z=1）
jne label          ; 不等则跳
jg  label          ; 有符号大于
jl  label          ; 有符号小于
ja  label          ; 无符号大于
jb  label          ; 无符号小于
jge label          ; 有符号 ≥
jle label          ; 有符号 ≤
jmp label          ; 无条件跳转
```

条件跳转依赖 **RFLAGS 标志位**：

| 标志 | 含义 |
|---|---|
| ZF | 结果为零 |
| SF | 结果为负（最高位为 1） |
| CF | 无符号运算产生进位/借位 |
| OF | 有符号运算溢出 |
| PF | 结果低 8 位中 1 的个数为偶数 |

ARM 则把条件直接写在指令后缀上（条件执行）：

```asm
cmp r0, #10
beq label       ; 相等跳转
bne label       ; 不等跳转
bgt label       ; 有符号 >
bge label       ; 有符号 ≥
movgt r2, #1    ; 若 r0 > r1 则 r2 = 1（条件执行，无需跳转！）
```

> ARM 的**条件执行**是精髓：单条指令可加条件后缀，避免跳转带来的流水线清空代价。

## 4.5 栈操作与函数调用

### 栈（Stack）

栈是"后进先出"（LIFO）结构，由 **SP/RSP 栈指针** 维护，通常**向低地址增长**。

```asm
; x86
push eax          ; rsp -= 8; [rsp] = eax
pop  ebx          ; ebx = [rsp]; rsp += 8

; ARM
push {r0-r3, lr}  ; 压入多个寄存器
pop  {r0-r3, pc}  ; 弹出并返回（pc=lr）
```

### 函数调用约定（x86-64 System V）

- 前 6 个整数参数依次放入 **RDI, RSI, RDX, RCX, R8, R9**
- 返回值放在 **RAX**
- **RSP 在调用时必须 16 字节对齐**
- 调用者保存：RAX, RCX, RDX, RSI, RDI, R8~R11
- 被调用者保存：RBX, RBP, R12~R15（需先压栈保护）

```asm
; 函数调用示例
main:
    mov edi, 10        ; 第一个参数
    mov esi, 20        ; 第二个参数
    call add_two       ; 调用函数（自动把返回地址压栈）
    ; 结果在 eax

add_two:
    push rbp           ; 保存旧帧指针
    mov  rbp, rsp      ; 建立新栈帧
    mov  eax, edi
    add  eax, esi
    pop  rbp           ; 恢复帧指针
    ret                ; 弹出返回地址并跳回
```

### 栈帧（Stack Frame）

每个函数在栈上占用一段区域叫栈帧，包含：返回地址、保存的寄存器、局部变量、参数。

```
高地址
  ┌─────────────────┐
  │ 调用者局部变量   │
  ├─────────────────┤
  │ 返回地址         │ ← ret 用
  ├─────────────────┤
  │ 保存的 RBP       │ ← RBP 指向这里
  ├─────────────────┤
  │ 局部变量区       │ ← 通过 [RBP-偏移] 访问
  ├─────────────────┤
  │ 参数区（若溢出）│
  └─────────────────┘ ← RSP
低地址
```

## 4.6 ARM 特有指令补充

```asm
bl  function      ; 跳转并链接：lr = 返回地址，再跳转（调用）
bx  lr            ; 跳转到 lr（函数返回，可切换指令集）
mrs r0, cpsr      ; 读状态寄存器
msr cpsr_c, r0    ; 写状态寄存器
svc #0            ; 软中断（系统调用入口，旧名 swi）
ldr r0, =0x12345678 ; 伪指令：加载任意 32 位立即数
```

# 五、寻址模式

寻址模式（Addressing Mode）决定指令如何找到操作数。

## 5.1 x86 寻址模式

| 模式 | 示例 | 说明 |
|---|---|---|
| 立即寻址 | `mov eax, 5` | 常数直接给 |
| 寄存器寻址 | `mov eax, ebx` | 操作数在寄存器 |
| 直接寻址 | `mov eax, [0x1234]` | 内存绝对地址 |
| 寄存器间接 | `mov eax, [ebx]` | 地址在寄存器 |
| 基址变址 | `mov eax, [ebx+ecx]` | 两寄存器相加 |
| 基址+变址+偏移 | `mov eax, [ebx+ecx*4+8]` | 完整形式（最常用） |

> `[ebx+ecx*4+8]` 这种形式完美映射 C 数组访问 `arr[i]`：基址=数组首地址、变址=i、比例因子=元素大小。

## 5.2 ARM 寻址模式

```asm
ldr r0, [r1]            ; 寄存器间接
ldr r0, [r1, #4]        ; 前索引：访问 r1+4，r1 不变
ldr r0, [r1, #4]!       ; 前索引+回写：访问 r1+4，然后 r1=r1+4
ldr r0, [r1], #4        ; 后索引：访问 r1，然后 r1=r1+4
ldr r0, [r1, r2, lsl #2] ; 基址+寄存器变址（可移位）
```

> 后索引 `[r1], #4` 非常适合遍历数组，一条指令完成"取数+指针自增"。

# 六、汇编与 C 语言的关系

## 6.1 C 语句对应的汇编

```c
int a = 5;           // mov eax, 5
int b = a + 3;       // add eax, 3
if (b > 0) {...}     // cmp eax, 0 / jle / ...
int arr[4];          // 栈上分配 16 字节
arr[i] = x;          // mov [rbp-16+rax*4], edx
```

## 6.2 查看 C 编译出的汇编

```bash
# 查看汇编
gcc -S hello.c -o hello.s
# 查看含 C 源码混排的汇编
gcc -g -O2 -c hello.c -o hello.o
objdump -dS hello.o
# 反汇编可执行文件
objdump -d a.out
# 在线反汇编神器：Compiler Explorer（godbolt.org）
```

## 6.3 内联汇编（GCC）

```c
int a = 10, b = 20, sum;
__asm__ volatile (
    "addl %%ebx, %%eax"
    : "=a"(sum)        // 输出操作数：eax → sum
    : "a"(a), "b"(b)   // 输入操作数：a→eax, b→ebx
    : "cc"             // 被破坏的寄存器/条件码
);
```

# 七、程序运行流程

## 7.1 编译链接全过程

```
源代码.c ──编译──▶ 汇编代码.s ──汇编──▶ 目标文件.o ──链接──▶ 可执行文件
```

- **编译（Compile）**：C → 汇编（编译器做语义分析、优化）
- **汇编（Assemble）**：汇编 → 机器码目标文件（带重定位信息）
- **链接（Link）**：合并目标文件、解析符号地址、生成可执行文件

```bash
gcc -S hello.c      # 只编译到汇编
gcc -c hello.c      # 编译+汇编到目标文件
gcc hello.o -o hello  # 链接成可执行文件
```

## 7.2 ELF 文件结构

Linux 下可执行文件是 ELF（Executable and Linkable Format）：

- **ELF Header**：魔数 `7f 45 4c 46`（`\x7fELF`）、架构、入口地址
- **Program Header**：段（Segment）加载信息
- **Section**：`.text`（代码）、`.data`（已初始化数据）、`.bss`（未初始化数据）、`.rodata`（只读数据）、`.symtab`（符号表）等

```bash
readelf -h a.out       # 查看 ELF 头
readelf -S a.out       # 查看 section
readelf -s a.out       # 查看符号表
objdump -t a.out       # 查看符号表
```

# 八、调试与逆向工具

| 工具 | 用途 |
|---|---|
| GDB | 断点、单步（`stepi` 单步指令）、查看寄存器（`info registers`）、查看内存（`x/20gx $rsp`） |
| objdump | 反汇编目标文件/可执行文件 |
| readelf | 分析 ELF 结构 |
| ghidra / IDA | 图形化逆向工具 |
| radare2 / rizin | 命令行逆向框架 |
| strace | 跟踪系统调用（验证汇编中 svc 调用是否生效） |
| ltrace | 跟踪库函数调用 |

GDB 常用汇编调试命令：

```bash
break main            # 断点
info registers        # 查看所有寄存器
x/8gx $rsp            # 查看栈顶 8 个 8 字节
stepi / nexti         # 单步执行一条指令
disassemble main      # 反汇编函数
p/x $rax              # 以十六进制打印 rax
```

# 九、进阶知识点

## 9.1 函数调用规范与 ABI

- **ABI（Application Binary Interface）** 定义了函数如何传递参数、返回、栈对齐、寄存器谁保存
- x86-64 有 SysV（Linux/Unix）和 Microsoft x64（Windows）两套
- 理解 ABI 才能写可互调的内联汇编和手写函数

## 9.2 系统调用（syscall）

Linux x86-64 系统调用流程：

```asm
section .data
msg db 'Hello', 0

section .text
global _start
_start:
    mov eax, 1        ; sys_write 系统调用号
    mov edi, 1        ; fd = stdout
    mov rsi, msg      ; 缓冲区地址
    mov edx, 5        ; 长度
    syscall           ; 触发内核

    mov eax, 60       ; sys_exit
    xor edi, edi      ; 退出码 0
    syscall
```

ARM 32 位则是 `svc #0`，系统调用号放在 R7。

## 9.3 中断与异常

- **中断**：外部硬件事件（定时器、串口），异步
- **异常**：指令执行引起（除零、缺页、非法指令），同步
- CPU 收到中断/异常后：保存现场 → 跳到中断向量表 → 执行 ISR → 恢复现场
- ARM 异常向量表地址：0x00000000（或 `VBAR` 寄存器指定）

## 9.4 寄存器窗口与流水线（了解）

- ARM 的异常模式有**影子寄存器**（FIQ 独享 R8~R12，加速中断响应）
- 流水线：取指→译码→执行，条件分支会**清空流水线**，这是 ARM 条件执行和预测技术的动机

# 十、学习路径与建议

1. **先定架构**：嵌入式/手机推荐 ARM（或 RISC-V，更简洁）；PC 端逆向/优化推荐 x86-64
2. **基础工具链**：GCC + GDB + objdump + readelf
3. **实践三件套**：
   - 写一个 `_start` 入口的裸汇编程序（不依赖 libc）
   - 用 C 写小函数，`-S` 看生成的汇编并逐条理解
   - 用 GDB `stepi` 单步观察寄存器和标志位变化
4. **进阶阅读**：架构官方手册（ARM ARM、Intel SDM）、ABI 规范、《Computer Systems: A Programmer's Perspective》（CSAPP）
5. **在线资源**：Compiler Explorer（godbolt.org）、ARM 官方汇编文档、x86-64 SysV ABI 文档

# 总结

汇编语言知识点可归纳为一条主线：

> **寄存器 ↔ 内存（寻址） ↔ 运算（算术/逻辑/移位） ↔ 控制流（比较/跳转/调用） ↔ 栈（压栈/弹栈/栈帧）**

掌握任意一种 ISA 的这几类指令，再学其他架构只需对比差异。汇编是理解计算机的"第一性原理"，也是通往内核、驱动、逆向、性能工程的必经之路。

> **一句话记住**：高级语言写"意图"，汇编写"指令"，机器码是"电信号"。三者间多一步解释或翻译，就多一层抽象与效率损耗——而汇编，正是离硬件最近、可读性最高的那一层。
