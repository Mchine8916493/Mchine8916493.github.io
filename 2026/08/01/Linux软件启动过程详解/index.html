Linux软件启动过程详解

Linux 软件启动过程详解

当你按下电源键，到屏幕上出现熟悉的桌面或登录提示符，中间发生了什么？本文从经典的 Linux 0.12 内核引导代码出发，逐阶段拆解一台 x86 机器「从上电到 shell」的完整软件启动链路，并对照现代 Linux 的演进。

一、启动流程总览

Linux 的启动是一条接力赛，每一棒都把自己的运行环境”打扫”好再交给下一棒：

整个过程中，CPU 需要完成一次实模式 → 保护模式的切换，内存从”一维线性”变为”分段 + 分页”的多层结构，控制权也从固件交给引导器、再从引导器交给内核、最后交给用户态进程。

二、第一阶段：固件与引导加载

2.1 BIOS 与 UEFI

项目 传统 BIOS UEFI
接口 16 位实模式中断调用（Int 13h 等） 64 位固件服务（Boot Services）
磁盘分区表 MBR（主引导记录） GPT（GUID 分区表）
引导方式 读取 MBR 第 512 字节引导代码 直接读取 EFI 系统分区（ESP）内的 .efi 引导程序
安全启动 无 Secure Boot 签名校验

上电后 CPU 首先执行复位向量（x86 复位后 CS:IP = 0xFFFF:0xFFF0，即物理地址 0xFFFFF0），跳入固件代码。固件完成 POST 自检后，按启动顺序查找可引导设备，把控制权交给引导加载程序。

2.2 Bootloader：GRUB2 的角色

GRUB2 的核心职责有三：

  1. 加载内核映像：从 /boot/vmlinuz-* 读取内核，放到内存中的约定位置；
  2. 加载 initramfs：把包含驱动和启动脚本的初始 RAM 文件系统装入内存；
  3. 设置启动参数：把 root=, quiet, splash 等内核命令行参数放入零页（Zero Page），供内核读取。

GRUB 加载完毕后，通过一条 jmp 或远跳转指令把 CPU 交给内核的第一行代码。

三、第二阶段：内核引导（Linux 0.12 经典流程）

Linux 0.12 的引导代码只有三个汇编文件，却能一步步把 CPU 从”裸机实模式”带到”C 语言环境”。这是理解整个内核初始化逻辑的最佳入口。

3.1 bootsect.s —— 引导扇区

  • BIOS 从磁盘 0 磁道 0 扇区读入 512 字节到物理地址 **0x7C00**，这就是引导扇区，即 bootsect.s 编译出的代码；
  • 它做的第一件事是把自身**从 0x7C00 搬到 0x90000**，腾出空间给后续模块；
  • 然后从磁盘加载 setup 模块到 0x90200，加载 system 模块（内核主体）到 0x10000；
  • 最后跳转到 0x90200 处的 setup 代码。

3.2 setup.s —— 读取硬件信息并进入保护模式

setup 模块承担两个任务：

  1. 收集硬件参数：通过 BIOS 中断读取内存大小（Int 15h 功能号 88h）、磁盘参数（Int 13h）、光标位置、显示模式等，存入以 0x90000 为基址的参数表（setup 把自己的代码段基址设为 0x90000），这些参数稍后供 main.c 使用；
  2. 切换到保护模式：把 cr0 寄存器的 PE 位（第 0 位）置 1，CPU 从 16 位实模式进入 32 位保护模式。

这里的关键是临时 GDT/IDT：在保护模式下，所有内存访问都要经过 GDT 查找段描述符。setup 设置了一个临时 GDT（只含内核代码段、数据段两个描述符，基址为 0、限长 8MB）和临时 IDT（全部为空），保证 ljmp 远跳转后 CPU 能正常工作。

3.3 head.s —— 中断、页表、跳转 C 语言

head.s 是引导的最后一棒，运行在保护模式下，按照真实源码顺序依次完成：

  1. 建立 IDT 与 GDT：call setup_idt 建立包含 256 个中断门的 IDT（初始全部指向 ignore_int 处理函数），call setup_gdt 建立真正的 GDT（内核代码段 0x08、数据段 0x10）；随后检查 A20 地址线是否真的打开、检测数学协处理器（check_x87）；
  2. 建立页目录和页表：setup_paging 在 0x0000 处建立页目录表，用 4 个页表（pg0~pg3，位于 .org 0x1000 起）覆盖前 16MB 物理内存，页目录项把线性地址恒等映射到相同的物理地址；
  3. **开启分页并跳转 main()**：设置 cr0 的 PG 位开启分页，然后通过 after_page_tables 把 main 的四个参数压栈、再 ret 跳转到 C 语言入口 main()（现代内核对应 start_kernel）。

3.4 main.c —— C 语言环境下的初始化

进入 main() 后，内核按真实源码中的顺序初始化各子系统（init/main.c）：

move_to_user_mode() 通过构造一个”假装从内核态返回”的栈帧触发中断返回指令 iret，让 CPU 特权级从 0 降到 3，从此任务 0 以用户态运行——这就是 Linux 第一个进程的诞生。

四、第三阶段：现代内核初始化

现代 Linux（x86-64）不再使用 bootsect/setup，引导汇编被压缩为 arch/x86/boot/ 下的少量代码，主体收敛到 C 语言的 **start_kernel()**（位于 init/main.c），初始化步骤包括：

步骤 功能
setup_arch() 解析启动参数、初始化内存布局、建立页表
trap_init() / init_IRQ() 建立中断向量表与硬件中断
mm_init() 伙伴系统、SLUB 分配器、VM 区初始化
sched_init() 进程调度器（CFS）初始化
vfs_caches_init() VFS 与文件系统缓存初始化
rest_init() 创建 kernel_init（PID 1）与 kthreadd（PID 2）两个内核线程

现代内核同时引入了 initramfs（initramfs-*.img）：早期用户态（initramfs）里自带驱动模块和 init 脚本，先挂载根文件系统所需的块设备驱动，再 switch_root 切换到真正的根分区，最后启动真正的 init。

五、第四阶段：用户态启动

5.1 init 进程（PID 1）

内核初始化完成后，kernel_init 通过 execve("/sbin/init") 变成用户态的 PID 1。PID 1 的特殊地位：

  • 它是所有进程的祖先（孤儿进程会被它收养）；
  • 若 PID 1 退出，内核会触发 panic（kernel panic - not syncing: Attempted to kill init!）。

5.2 systemd 的目标（Target）与服务（Unit）

传统发行版用 SysVinit 的 rc 脚本按运行级别启动服务；现代主流用 systemd：

  • Unit：把要启动的东西抽象成单元（服务 .service、挂载 .mount、套接字 .socket 等）；
  • Target：把一组 Unit 打包成”目标状态”（multi-user.target、graphical.target），取代 SysV 运行级别；
  • systemd 采用并行启动：互相独立的服务同时拉起，大幅缩短开机时间；
  • 系统最后执行 getty 打开终端，或启动显示管理器（gdm/sddm）进入桌面。

六、贯穿全程的关键机制

6.1 实模式 → 保护模式

模式 寻址方式 地址空间 用途
实模式 段基址×16 + 偏移 1MB 引导阶段，兼容 BIOS 调用
保护模式 段描述符 + 分页 4GB+ 内核与用户态运行

切换靠修改 cr0 的 PE 位完成，切换后段选择子必须重新加载，且需要一次远跳转刷新流水线。

6.2 分段与分页

保护模式的内存访问两级转换：分段（逻辑地址 → 线性地址）→ 分页（线性地址 → 物理地址）。Linux 采用平坦内存模型，把所有段的基址设为 0，弱化分段、强化分页；页表结构从 0.12 的两级（页目录+页表）演进到 x86-64 的四级（PGD/PUD/PMD/PTE）。

6.3 系统调用入口

0.12 时代所有系统调用统一走 int 0x80 中断，中断处理程序根据 eax 里的系统调用号查表跳转；现代内核已用 syscall/sysret 指令取代（更快），但”用户态陷入内核态执行”的模型不变。

6.4 特权级转换的常见入口

启动过程中特权级切换一共发生两次关键跳变：

  1. **实模式(0) → 保护模式(0)**：setup.s 打开 PE 位，仍在内核态；
  2. **内核态(0) → 用户态(3)**：main() 结束时用 iret 构造返回帧，任务 0 从此以用户态执行——之后每次用户态调用系统调用，都经 int 0x80 / syscall 陷入内核再返回。

七、小结

Linux 启动过程可以浓缩成一句话：

固件找引导器，引导器加载内核，汇编铺好内存与中断环境，C 语言初始化子系统，最后把控制权交给用户态 PID 1。

每一棒都只做”自己够得着”的事：bootsect 只知道搬自己、setup 只负责拿参数和开保护模式、head 负责页表和 IDT、main/start_kernel 负责所有子系统、systemd 负责拉起整个用户态世界。理解了这条接力链，无论是排查内核 panic、理解开机慢的原因，还是为嵌入式设备裁剪启动流程，都能有的放矢。
