Linux内存管理详解

Linux 内存管理详解

内存管理（Memory Management）是 Linux 内核中最核心、也最复杂的子系统之一。它负责物理内存的分配与回收、虚拟地址空间的映射、缺页处理、进程隔离与共享等众多任务。本文从硬件基础出发，自底向上梳理 Linux 内存管理的整体脉络。

一、从地址空间说起

1.1 三种地址

在操作系统视角下，地址分为三种：

地址类型 含义 示例
逻辑地址 程序指令中使用的地址 0x400000
线性地址（虚拟地址） 逻辑地址经段机制转换后得到 0x7ffc1234
物理地址 实际访问内存芯片的地址 0x1000

在 x86-64 架构下，Linux 默认采用平坦内存模型（Flat Model），段机制被弱化（所有段的基址为 0、限长最大），逻辑地址与线性地址直接相等。真正的核心转换是虚拟地址 → 物理地址，由分页机制（Paging）完成。

1.2 虚拟内存的意义

  • 进程隔离：每个进程拥有独立的虚拟地址空间，互不可见。
  • 内存保护：内核态/用户态通过页表权限位隔离。
  • 地址空间扩展：虚拟地址空间（64 位下巨大）可以远大于物理内存。
  • 延迟分配：先映射虚拟地址，真正使用时才分配物理页（Demand Paging）。
  • 共享与写时复制：fork 时子进程共享父进程物理页，写入时才复制（COW）。

二、分页机制与页表

2.1 页与页帧

物理内存按固定大小划分，称为页帧（Page Frame）；虚拟地址空间按同样大小划分，称为页（Page）。默认页大小在 x86-64 下为 4KB，也支持 2MB 的大页（Huge Page）。

2.2 多级页表

64 位地址空间如果只用一级页表，需要 2^52 个页表项，完全不现实。因此 x86-64 使用四级页表：

  • PGD：Page Global Directory
  • PUD：Page Upper Directory
  • PMD：Page Middle Directory
  • PTE：Page Table Entry

每级 9 位索引（512 项 × 8 字节 = 4KB，恰好占一个页），四级共覆盖 48 位地址空间。多级结构的好处是：进程通常只使用很小的地址空间，许多中间目录项可以为空，不必为整个地址空间都建页表。

2.3 页表项的关键位

一个典型的 PTE 包含：

位 含义
Present (P) 页是否在物理内存中
Read/Write (R/W) 可写标志
User/Supervisor (U/S) 用户态是否可访问
Accessed (A) 最近是否被访问（供换出算法参考）
Dirty (D) 是否被写入（决定写回磁盘与否）
NX 禁止执行位（DEP 防护）

三、物理内存管理

3.1 伙伴系统（Buddy System）

Linux 以页为单位管理物理内存，采用伙伴系统算法：把空闲页按 2 的幂次分成 11 个链表（order 0~10，即 4KB ~ 4MB）。

分配时遵循”大块拆分、小块合并“原则：

  • 请求 order n 的内存：若 n 链上有空闲块，直接分配；
  • 否则向上找 order n+1，拆分一半（互为”伙伴”）分配，另一半挂到下一级链表；
  • 释放时检查伙伴是否空闲，若空闲则两两合并升级，减少外部碎片。

3.2 SLAB/SLUB 分配器

伙伴系统的最小单位是一页（4KB），但对于内核频繁创建销毁的小对象（如 task_struct、inode），一页太大了。因此内核在伙伴系统之上实现 SLAB 分配器（现代内核默认 SLUB）：

  • 将连续页划分为固定大小的对象缓存（Cache）；
  • 同一类型的对象复用同一 Cache，避免反复初始化；
  • 支持每 CPU 局部缓存，减少锁竞争；
  • 空闲对象用 freelist 串起来，分配 O(1)。

3.3 内存节点与区域

在 NUMA 架构下，物理内存按 CPU 访问延迟划分为多个节点（Node），每个节点内部再分为多个区域（Zone）：

区域 说明
ZONE_DMA 供 ISA DMA 使用（低 16MB）
ZONE_DMA32 供 32 位 DMA 设备使用
ZONE_NORMAL 直接映射区（内核线性映射）
ZONE_HIGHMEM 高端内存（32 位时代遗留，64 位已消失）
ZONE_MOVABLE 可迁移页，供内存热插拔与内存规整

四、内核地址空间布局

以 x86-64 为例，内核使用高地址部分（0xffff888000000000 起），用户空间使用低地址部分（0x0000000000000000 ~ 0x00007fffffffffff，共 128TB）。

内核地址空间的主要区域：

区域 起始地址 说明
直接映射区 PAGE_OFFSET（ffff888000000000） 物理内存直接线性映射，virt_to_phys 直接换算
vmalloc 区 ffffc90000000000 非连续内存映射，用于模块、大块分配
vmemmap 紧随 vmalloc 每个物理页对应一个 struct page
内核代码/模块 高地址 内核镜像、模块加载区

direct map 与 vmalloc 的区别：

  • 直接映射：物理地址 = 虚拟地址 - 固定偏移，转换快、TLB 友好，但可能产生碎片；
  • vmalloc：页在物理上可以不连续，通过页表动态映射，适合大块但零散的分配。

五、进程地址空间（mm_struct 与 VMA）

每个进程的虚拟地址空间由一个 mm_struct 描述，其中最重要的结构是虚拟内存区（VMA, Virtual Memory Area）——用红黑树 + 链表组织的一段段连续虚拟地址区间：

每个 VMA 记录：

  • 起始/结束地址（vm_start、vm_end）
  • 访问权限（读/写/执行）
  • 标志（私有/共享、锁定等）
  • 关联的文件或匿名页

mmap() 系统调用就是在进程地址空间中创建新的 VMA 并映射页表。

六、缺页异常（Page Fault）

当 CPU 访问的虚拟地址没有对应的物理页映射时，触发缺页异常，内核通过 do_page_fault → 按 VMA 类型分发处理：

缺页类型 触发场景 处理方式
匿名缺页 首次访问堆/栈/BSS 分配新页框并清零
文件缺页 首次访问 mmap 的文件页 从页缓存（Page Cache）读入
写时复制（COW） fork 后子进程首次写入 复制物理页、更新权限为可写
栈扩展 压栈超过当前 VMA 上限 扩展栈 VMA 并分配页
大页折叠 THP 启用 将 4KB 页合并为 2MB 页
非法访问 越界/无权限 向进程发送 SIGSEGV

写时复制（COW）

fork() 创建子进程时，并不真正复制全部物理内存，而是：

  1. 父子进程共享全部物理页；
  2. 将所有共享页的 PTE 设置为只读；
  3. 任何一方写入时触发缺页，内核复制该页并恢复双方的读写权限。

这使得 fork + exec 的开销极低，是进程创建性能的关键。

七、用户态内存分配路径

  • brk 调整堆顶指针，适合小块、频繁分配的场景；
  • mmap 创建独立的匿名映射，超过 M_MMAP_THRESHOLD（默认 128KB）的大块直接走 mmap，free 时立即归还内核。

八、内存回收与换出

当内存紧张时，内核通过 kswapd 内核线程和 直接回收（direct reclaim） 回收内存：

8.1 LRU 链表

匿名页与文件页分别挂在不同优先级的 LRU 链表中：

页面首次访问进入 inactive 链表，再次访问时被”晋升”到 active 链表；回收时优先从 inactive 尾部取。

8.2 回收方式

方式 对象 说明
回写 脏文件页 写回磁盘后释放
丢弃 干净文件页 直接释放，需要时再从磁盘读
换出 匿名页 写入 swap 分区/文件后释放

8.3 内存水位（Watermark）

每个内存区域有三个水位：

  • high：内存充足；
  • low：低于此水位时 kswapd 被唤醒开始回收；
  • min：低于此水位时，只有原子分配才被允许，普通分配进入直接回收。

8.4 OOM Killer

当内存严重不足且回收无法缓解时，内核触发 OOM Killer：遍历所有进程，根据 oom_score（内存占用、进程重要程度、root 权限等加权）挑选”罪大恶极”的进程并杀掉，以释放内存。可通过 echo 2 > /proc/sys/vm/oom_kill_allocating_task 调整策略，或 echo 1 > /proc/<pid>/oom_score_adj 保护关键进程。

九、其他重要机制

9.1 页缓存（Page Cache）

Linux 对文件内容缓存于 Page Cache 中，读写文件先与 Page Cache 交互：

  • 读：命中缓存直接返回，未命中则从磁盘读入并缓存；
  • 写：写入缓存标记脏页，由 pdflush（现为 flush 线程）异步回写磁盘；
  • 这就是”free 命令中 cache 占用大”的原因——空闲内存应尽量用作缓存。

9.2 透明大页（THP）

自动将相邻的 4KB 页合并为 2MB 大页，减少 TLB 缺失，但可能增加内存碎片与延迟（/sys/kernel/mm/transparent_hugepage/enabled 可开关）。

9.3 内存规整（Compaction）

将碎片化的页框迁移整理成连续的大块，供大页分配使用（vm.compact_memory）。

十、常见排查工具

总结

层次 机制 职责
硬件 分页、四级页表、TLB 地址转换
物理内存 伙伴系统 + SLUB 页/对象的分配回收
内核地址空间 直接映射 + vmalloc 内核自身的虚拟地址
进程地址空间 mm_struct + VMA 用户态虚拟内存
缺页处理 do_page_fault 惰性分配、COW、加载文件
内存压力 kswapd + LRU + OOM 回收与救急

Linux 内存管理的核心哲学可以概括为一句话：**”延迟分配、按需加载、最大化利用、协同回收”**——虚拟化带来的灵活性，加上多层缓存与惰性机制，让有限的物理内存在海量进程间高效流转。
